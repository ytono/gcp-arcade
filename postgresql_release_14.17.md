| Improve behavior of libpq's quoting functions (Andres Freund, Tom Lane) § § §<br>The changes made for CVE-2025-1094 had one serious oversight: PQescapeLiteral() and PQescapeIdentifier() failed to honor their string length parameter, instead always reading to the input string's trailing null. This resulted in including unwanted text in the output, if the caller intended to truncate the string via the length parameter. With very bad luck it could cause a crash due to reading off the end of memory.<br>In addition, modify all these quoting functions so that when invalid encoding is detected, an invalid sequence is substituted for just the first byte of the presumed character, not all of it. This reduces the risk of problems if a calling application performs additional processing on the quoted string. | バグ修正   | libpqのクォーティング関数の挙動を改善 (Andres Freund, Tom Lane) § § §<br>CVE-2025-1094に対する変更には、深刻な見落としがありました。PQescapeLiteral()とPQescapeIdentifier()が文字列の長さパラメータを尊重せず、入力文字列の末尾のnullまで常に読み取っていました。その結果、呼び出し元が長さパラメータで文字列を切り捨てようとした場合、不要なテキストが出力に含まれることになりました。運が悪ければ、メモリの終端を超えて読み取ることでクラッシュを引き起こす可能性がありました。<br>さらに、これらのクォーティング関数をすべて修正し、無効なエンコーディングが検出された場合、想定される文字全体ではなく、最初のバイトのみを無効なシーケンスに置き換えるようにしました。これにより、呼び出し元のアプリケーションがクォートされた文字列に追加の処理を実行する場合の問題のリスクを軽減します。 | libpqのクォーティング関数(PQescapeLiteral, PQescapeIdentifier)において、文字列長パラメータが無視され、意図しない文字列が含まれたり、メモリ外読み込みによるクラッシュが発生する可能性があった問題を修正。また、無効なエンコーディング検出時の処理を改善し、影響範囲を縮小。 | 高     | PostgreSQLをアップデートしてください。アプリケーション側でPQescapeLiteral()またはPQescapeIdentifier()を使用している場合は、アップデート後に期待通りの動作となるか確認してください。 |
